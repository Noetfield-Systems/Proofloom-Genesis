# Product Requirements — Genesis to Agentic Economy

## North-star loop
Discover → Join → Learn → Contribute → Verify → Improve → Reward → Reputation → More opportunities. The core promise is a real, traceable, quality-adjusted contribution rather than a token for meaningless clicks.

## Six roles
Explorer (no code), Vibe Builder (prompt-driven), Professional Builder (code/PR), Maintainer (review), Sponsor (funded mission), Community Participant (governance and ecosystem). Initial application provides shared entry, different quests, review and sponsor inquiry; advanced role management remains planned.

## Genesis implementation
A visitor sees current actual mission inventory and live metrics. A builder registers without a wallet, opens a mission, sends a 25–6000 character contribution with optional HTTPS evidence, receives a durable unique submission and tracks review in Profile. Authorized operator reviews with a rationale, records an accepted decision once, awards mission XP once and creates a public proof page. Referral credit only on an invitee's accepted submission. Sponsor inquiries are persisted but **not** paid bounties.

## Extension criteria
1. Real self-contained open-source sandbox project and authorized external projects.
2. Evidence classification, clustering, fair severity scoring and persistent issues.
3. Authenticated project-level WorkPacket dispatch to selected AI/human executor.
4. Real PR, automated tests, independent verification receipts, release and revalidation.
5. Paid sponsor budgets, verified settlement, freelancer reputation, distinct token allocations.
6. Community governance and configurable season rules, with actual participation metrics.

## Important user stories
- Beginner can reproduce a bug and receive credit equal to a code contributor if impact warrants.
- Builder can attach a GitHub PR and see whether it was reviewed or shipped.
- Sponsor can set clear acceptance rubric and funding conditions before inviting work.
- Admin can reject duplicate spam without rewarding it.
- Participant can see the difference between XP, conditional token allocation and received money.

## Current limits
One demonstration project; one contribution per account+mission; no email verification; no project tenancy API, agent execution, wallet, external sponsor transaction, live token or rewards claim. These are explicit roadmap items, not hidden behind marketing claims.

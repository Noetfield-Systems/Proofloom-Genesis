## Variables and access

Set `DATABASE_URL=${{Postgres.DATABASE_URL}}`, `NODE_ENV=production`, `PORT=3000`; reference the previously configured secret values for `OPERATOR_REVIEW_KEY`, `BRIDGE_API_KEY`, `VERIFIER_API_KEY`. `BRIDGE_REPOSITORY=Noetfield-Systems/Proofloom-Genesis` documents the intended repo but does **not** grant GitHub App/agent access. `BRIDGE_ENABLED=false` until a functioning authorized runner is verified. `QA_ENABLED=false` normally. Never place actual secrets in GitHub or user-visible logs.

## Verification and rollback

- Railway `environment_status`: Web and Postgres should be Online with deployment SUCCESS.
- `POST /__smoke`: HTTP 200 verifies public routes plus a rollback-only database write.
- `POST /__i18n_smoke`: HTTP 200 verifies 60 page-language combinations (10 languages, six public routes), selected locale, HTML direction, translated headings and clean language return path.
- Unauthenticated `POST /api/v1/bridge/event`: HTTP 401.
- `GET /health`: 200; `GET /api/v1/status`: truthfully flags non-live financial/agent capabilities.
- If new Docker build fails, inspect Railway build/deploy logs; original Railway Function remains online as fallback. Do not drop/replace Postgres or run destructive migrations to resolve a source build issue.

## Contribution lifecycle

`/operator` → short-lived privileged review session → accept/reject with rationale. Accepted work awards XP transactionally, creating a triage-ready WorkPacket reference. Agent dispatch and verified merge remain separate from review acceptance. Enrollment requires no wallet. Token payouts and paid bounties are not live.
